Typed data access / SPFx

Keep the data layer close to the platform.

A dependency-free TypeScript ESM package for SharePoint REST list CRUD and Microsoft Graph JSON batch results, with a small transport boundary your host controls.

See the quickstart ↓ Read the source ↗

Small by design. Authentication, authorization, tenant discovery, and network policy stay with the SPFx or browser host.

host-transport.ts
import { DataClient } from "spfx-data-kit";
import type { RequestTransport } from "spfx-data-kit";

const transport: RequestTransport = {
  request: (url, options) => fetch(url, options),
};

const client = new DataClient(transport, {
  cache: { maxEntries: 100, ttlMs: 30_000 },
});

Host seam: use an existing authenticated request client here when the app needs one.

What is in the package

Native pieces, composed plainly.

The runtime owns request coordination and typed service adapters. It does not try to become your auth layer, state store, or UI framework.

01 / transport

Bring the request policy.

Inject any host that implements RequestTransport: SPFx, browser fetch, tests, or another authenticated runtime.

02 / client

Deduplicate and bound GETs.

In-flight GET deduplication, optional bounded in-memory TTL caching, invalidation, diagnostics, and bounded GET retries.

03 / SharePoint

Keep list CRUD typed.

Paging, select/expand/filter/orderBy/top, mapped entities, create/update/delete, and per-item ETags for SharePoint REST lists.

04 / Graph

Parse JSON batches safely.

Graph requests return typed data and ETags; batch results preserve child status, headers, bodies, and failures.

05 / consistency

Make writes explicit.

SharePoint writes can send IF-MATCH, invalidate list reads, and re-read the resulting item after a write.

06 / errors

Keep failure useful.

Stable DataError.kind values expose status, cause, and retry timing without leaking service payloads into messages.

The shape of a request

One boundary. Several useful adapters.

Host

Supplies URL discovery, credentials, headers, and network access.

Client

Coordinates GET identity, cache, dedupe, retries, and diagnostics.

SharePoint

Builds list URLs and maps REST rows into your entity type.

Graph

Builds requests and validates the service's batch response shape.

Your app

Receives typed results and decides how to render or persist them.

Honest boundaries

Useful because the limits are visible.

Included

Transport contracts, GET coordination, typed SharePoint REST list operations, Graph requests, JSON batch parsing, ETag handling, stable errors, and a capability manifest.

Not included

Authentication, authorization, tenant discovery, persistent or offline storage, UI components, telemetry, server code, and PnPjs.

Service limits remain real

Graph JSON batches are capped at 20 child requests. SharePoint batch children are GET-only in this adapter. The host and service still own their policies.

No performance theatre

There are no fabricated benchmarks, tenant-wide claims, or production-scale guarantees on this page. Inspect the source and run the checks for the behavior you need.
